## pytest store: 17 memories, 65 accesses, 16 outcomes (15 negative)

- [1] uses=15 outcomes=4 value=-1.00 — pytest codebase: arbitrary user values written to the terminal (e.g. fixture params in src/_pytest/setuponly.py::_show_fixture_action) must be rendered with _pytest._io.saferepr.saferepr(obj, maxsize=42), not str.format()/str(), because str() on bytes raises BytesWarning under `python -bb` (how pytest's own CI runs). Note saferepr quotes strings, so display changes from [foo] to ['foo'] — testing/test_setuponly.py's param-display tests assert that exact format.
- [2] uses=11 outcomes=3 value=-1.00 — pytest codebase gotcha (src/_pytest/mark/expression.py): never emit ast.Name nodes whose id is "True", "False", or "None" — compile() of such an AST raises ValueError on release CPython 3.8+ and aborts with a compiler_nameop assertion on debug builds (bpo-40870). The -k/-m expression compiler therefore prefixes every identifier with IDENT_PREFIX = "$" when building the AST, and MatcherAdapter.__getitem__ strips it (key[len(IDENT_PREFIX):]) before calling the matcher. Any change to identifier handling there must preserve this prefix round-trip.
- [3] uses=9 outcomes=3 value=-1.00 — pytest codebase (src/_pytest/skipping.py): pytest_runtest_makereport is a single if/elif chain, so branch ORDER is semantics. The `elif item.config.option.runxfail: pass # don't interfere` guard must come AFTER the skipped-by-mark location-fixup branch (the one matching skipped_by_mark_key + rep.skipped + tuple longrepr, which rewrites longrepr to item.reportinfo() so -rs points at the test, not skipping.py). If runxfail is checked first it swallows that fixup and `-rs --runxfail` reports skip locations as src/_pytest/skipping.py:NNN. --runxfail must only affect xfail branches, never plain skip/skipif.
- [4] uses=9 outcomes=1 value=-1.00 — pytest codebase (src/_pytest/skipping.py): xfail mark evaluation is cached in item._store[xfailed_key], set at setup and at the START of the pytest_runtest_call hookwrapper. A marker added dynamically inside the test body (request.node.add_marker) appears during the yield, so the wrapper must RE-refresh the store after yield (`xfailed = item._store.get(xfailed_key, None); if xfailed is None: re-run evaluate_xfail_marks`) or pytest_runtest_makereport sees the stale None and reports a plain failure instead of xfail. The store comment "Can be refreshed during call if None" encodes this contract: None means "no xfail seen yet, safe to re-evaluate"; a real Xfail result is never re-evaluated.
- [5] uses=5 outcomes=1 value=-1.00 — pytest codebase (src/_pytest/capture.py): every TextIOWrapper used for capture must be constructed with newline="" or reading the captured text back applies universal-newline translation and silently converts \r to \n (the pytest 6.0.0rc1 capfd regression). CaptureIO (capsys path) already passes newline=""; FDCaptureBinary's EncodedFile over TemporaryFile(buffering=0) needs it too. The translation happens on the read in snap() (seek(0)+read()), not on write, so tests that only inspect the file bytes won't catch it.
- [6] uses=1 outcomes=1 value=+1.00 — pytest codebase (src/_pytest/logging.py): caplog.handler is NOT per-test — the property reads item._store[caplog_handler_key], which is the LoggingPlugin's single shared LogCaptureHandler reused across all tests (a pytest 6.0 change). Therefore any state set on it in LogCaptureFixture (e.g. set_level calling self.handler.setLevel) leaks into subsequent tests unless _finalize() explicitly restores it. Pattern: save the pre-test handler level once (guard `if self._initial_handler_level is None` so multiple set_level calls keep the ORIGINAL, not the previous call's value) and restore it in _finalize alongside _initial_logger_levels. at_level() already restores the handler level itself; set_level relies on _finalize.
- [7] uses=3 outcomes=0 value=+0.00 — pytest codebase (src/_pytest/pathlib.py): visit() is the single shared breadth-first directory walker used by collection (Session/Package) and assertion-rewrite discovery. Its recursion check must be entry.is_dir() WITHOUT follow_symlinks=False — passing follow_symlinks=False makes symlinked directories silently vanish from collection (the pytest 6.1.0 regression from commit b473e515, issue #7981). is_dir() follows symlinks by default; the norecursedirs/recurse callback is the right place to prune, not the symlink flag.
- [8] uses=4 outcomes=0 value=+0.00 — pytest codebase (src/_pytest/compat.py): in num_mock_patch_args, comparing @patch's p.new against the mock DEFAULT sentinels must use identity (any(p.new is s for s in sentinels)), never `p.new in sentinels` — list `in` falls back to == when identity fails, and user-supplied new= values (e.g. numpy arrays) return element-wise arrays from ==, so bool() raises ValueError and aborts collection (pytest issue #4413). General rule: pytest internals must never run ==/bool() on arbitrary user objects; compare against sentinels with `is`. Handy no-numpy repro: a class whose __eq__ returns an object whose __bool__ raises ValueError faithfully simulates ndarray comparison semantics.
- [9] uses=2 outcomes=1 value=-1.00 — pytest codebase (src/_pytest/reports.py): BaseReport._to_json/_from_json are the xdist wire format for reports. Gotcha: ExceptionChainRepr.reprtraceback/.reprcrash are ONLY the last link of the chain (set from chain[-1] in _pytest/_code/code.py), so any serializer that consumes just those two attributes silently drops chained exceptions (__cause__/__context__ — the "direct cause"/"during handling" sections). The serialized longrepr dict must carry a "chain" key (list of (reprtraceback, reprcrash, description) triples; None for non-chain), and _from_json must rebuild ExceptionChainRepr when chain is truthy, else ReprExceptionInfo. Easy repro without xdist: a conftest hookwrapper for pytest_runtest_makereport that round-trips the report through pytest_report_to_serializable → json.dumps/loads → pytest_report_from_serializable and force_result()s the copy.
- [10] uses=2 outcomes=1 value=-1.00 — pytest codebase (src/_pytest/pastebin.py): the bpaste.net pastebin rejects some pytest console outputs with HTTP 400 when submitted with lexer=python3/python — the lexer must be "text" because a session log is arbitrary text, not Python code (pytest issue #5806). - [11] uses=1 outcomes=0 value=+0.00 — pytest codebase (src/_pytest/pathlib.py::unique_path, issue #5819): never canonicalize a path that will later be imported by lowercasing it (os.path.normcase on Windows) — Python's import machinery (importlib FileFinder) matches directory names case-SENSITIVELY even on case-insensitive filesystems (Windows/APFS), so a conftest under C:\...\Python\PIsys imported via the lowercased path fails with ModuleNotFoundError: No module named 'python'. Correct canonicalization is pathlib Path(str(p)).resolve(), which returns the true on-disk casing on Windows (via _getfinalpathname); py.path.local.realpath()/os.path.realpath on py<3.8 does NOT case-correct. - [12] uses=2 outcomes=1 value=-1.00 — pytest codebase (src/_pytest/python.py::Package.collect, issue #6194): Package.collect() must never import the package's own __init__.py eagerly — an unconditional import at the top of collect() (added by #5831 for skip-marks) broke collection of unimportable-but-testless packages (e.g. Windows-only packages on Linux). Two ordering facts make the correct fix non-obvious: (1) skipping's pytest_runtest_setup is @hookimpl(tryfirst=True) and runs BEFORE Package.setup(), so mounting markers at setup time misses the first test in the package (that was bug #5830); (2) markers propagate live at runtime via Node.iter_markers walking listchain()'s own_markers — they are NOT snapshotted into items at collection. Therefore mounting the package obj at ANY point while the collect() generator is consumed (even after yielding children) is early enough. Fix shape: wrap the collect body (`for node in self._collect(): self._mount_obj_if_needed(); yield node`) so the import happens only once the package yields its first collected node. Upstream 5.2.4 instead fully reverted #5831 (re-breaking #5830); the lazy-mount keeps both fixed.
- [13] uses=0 outcomes=0 value=+0.00 — pytest codebase (src/_pytest/python.py, PyobjMixin.getmodpath): the trailing `s.replace(".[", "[")` was a relic of pre-pytest-4 yield/Generator tests, whose child items were literally named "[0]" so the "."-join produced "test_func.[0]". With Generators removed it only corrupted parametrized IDs containing ".[" (e.g. test_boo[..[] displayed as test_boo[.[] in failure headlines and reportinfo/location, which also broke vscode-python discovery). Correct fix is `return ".".join(parts)` — nothing in testing/ depends on the replace. getmodpath feeds reportinfo() → item.location → report headlines, so name mangling there surfaces in terminal output and IDE integrations, not collection.
- [14] uses=0 outcomes=0 value=+0.00 — pytest codebase: `pytest --fixtures` privacy is controlled purely by the fixture name prefix — _showfixtures_main and _show_fixtures_per_test in src/_pytest/python.py skip any argname starting with "_" unless -v is given. So internally generated fixtures must pass an underscore-prefixed name= to @pytest.fixture; e.g. _make_xunit_fixture in src/_pytest/unittest.py (setUpClass/setup_method autouse fixtures) uses name=f"_unittest_{setup_name}_fixture_{obj.__qualname__}". - [15] uses=0 outcomes=0 value=+0.00 — pytest codebase (src/_pytest/logging.py): the caplog_records_key stash maps each phase ("setup"/"call"/"teardown") to the shared LogCaptureHandler.records list BY REFERENCE (assigned in _runtest_for right after reset()). Two distinct semantics are required: caplog.clear() must empty the list IN PLACE (handler.clear() → self.records.clear()) so the stash-held reference stays live, while the per-phase reset() must REBIND (self.records = []) so each phase's stash entry is a distinct list — clearing in place in reset() would alias all phases to one list; rebinding in clear() freezes get_records() (issue #9877). Hence LogCaptureHandler deliberately has both reset() and clear().
- [16] uses=1 outcomes=0 value=+0.00 — pytest codebase (src/_pytest/unittest.py, TestCaseFunction.runtest, issue #10060): the --pdb tearDown-postponement guard must detect skips at BOTH levels — `_is_skipped(self.obj) or _is_skipped(self.parent.obj)` (parent is the UnitTestCase collector whose .obj is the class). Gotcha: `unittest.skip` on a class sets `__unittest_skip__` on the class only; a bound test method does NOT expose it via getattr, so `_is_skipped(self.obj)` alone (the #7215 fix) misses class-level skips. Failure mode: with --pdb, tearDown is swapped for a no-op and stashed in `_explicit_tearDown`, which `teardown()` later calls unconditionally — running the real tearDown for a test unittest never set up. - [17] uses=0 outcomes=0 value=+0.00 — pytest codebase (src/_pytest/mark/structures.py, issue #7792): class marks must be collected via the MRO, and three details make the fix non-obvious. (1) get_unpacked_marks for a class must merge each MRO entry's OWN __dict__.get("pytestmark") — plain getattr resolves only the first class in the MRO, so `class TestDings(Foo, Bar)` silently loses Bar's marks. (2) store_mark must call get_unpacked_marks(obj, consider_mro=False): the decorator historically COPIED inherited marks into the subclass's own pytestmark; if it still did while collection also walks the MRO, base-class marks would be duplicated. (3) Iterate `reversed(obj.__mro__)` (base classes first) to preserve the pre-fix ordering that the old copy-on-store behavior produced — plain __mro__ order reversed observed mark order (upstream regression #10447). Extra gotcha: a class's pytestmark attribute may be a single MarkDecorator, not a list (`pytestmark = pytest.mark.parametrize(...)`), so the not-a-list normalization must run per MRO entry, not once on the merged result (upstream regression: TypeError 'MarkDecorator' object is not iterable).
